# インターン×企業 スカウトサービス 設計リポジトリ

エンジニア職の長期インターンを探す学生と、学生を探す企業をつなぐ「募集・スカウトサービス」のプロトタイプの、**設計書**を置いているリポジトリです。

- ここにあるのは設計（何を・なぜ・どう作るか）だけです。実装のコードは置いていません
- 実装では、バックエンドに Rails（レイルズ）、フロントエンドに Next.js（ネクストジェイエス）を使う予定です
- 設計書は「AI が読めば、そのまま実装に移れる」具体さになるまで、相談と更新を繰り返しています

## フォルダの見方

```
.
├── README.md      … このファイル
├── CLAUDE.md      … 設計を手伝う AI（Claude）への指示書
├── MEMO.md        … 作業用のメモ
├── premise/       … 出発点の資料
│   ├── 内容.md    … 作るもののシナリオと要件
│   └── 進め方.md  … Phase 0〜8 の進め方の計画
├── designs/       … 設計書の本体（常に最新の状態に保つ）
└── minutes/       … 議事録（005 から）
```

- premise/ は出発点として残しているもので、内容は更新しません。今の状態は designs/ を見てください
- 議事録1〜4 は、内容を designs/ に統合済みです。minutes/ には、議事録5 以降を置きます

4. データベース.md：データの持ち方

## 設計の進め方

- AI は、提案・反論・主張に **PR1、PR2 …** の通し番号を付けます（Proposal の略。学生側の画面番号 S1〜S9 と区別するため）
- 開発者は、番号ごとに承認か反論をします。触れなかった番号は「未決」とし、設計書には入れません
- 決まったことは designs/ に反映し、古い内容は新しい内容に置き換えます。途中で変わった点は、その他決め事.md の13章に「旧 → 新」の形で残します
- 話し合いのたびに、「決めたこと」と「決めなかったこと（未決・保留）」を minutes/ の議事録に残します
- 詳しい決まりは [CLAUDE.md](CLAUDE.md) にあります

## 設計書で使う主な表記

| 表記 | 意味 |
| --- | --- |
| C1〜C10 | 企業側の画面番号 |
| S1〜S9 | 学生側の画面番号 |
| 【コア】【強み】【仕上げ】【後付け】 | 段階タグ。実装の優先順（ページ設計.md の 6-4） |
| 募集／応募 | 募集は企業が出すもの、応募は学生がするもの（厳密に呼び分ける） |
| やりとり | 「募集×学生」の組み合わせ1件。応募・スカウトのどちらから始まっても同じ |
| マッチ | 企業と学生の双方が意思表示して、会話ができるようになること（採用の決定ではない） |
