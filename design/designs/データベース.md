## 8. データベース

### 8-1. 共通ルール

- データベースは PostgreSQL
- すべてのテーブルに次の3列を自動で付ける（各表では省略）
  - id：bigint、主キー（PK（ピーケー））
  - created_at：作成日時
  - updated_at：更新日時
- 外部キー（FK（エフケー））には、すべてインデックスを付ける（Rails の references（リファレンシズ）で作ると自動で付く）
- enum（イーナム）は `{ unpublished: 0, published: 1 }` のように番号を明示して書く。新しい値は末尾の番号で足す
- マスタの初期データ（seed（シード））は、id ではなく code か name（UNIQUE（ユニーク））で管理し、不要になっても削除しない
- 必須項目の確認方法は本書5-9のとおり
- 権限、状態の遷移、「掲載中のみスカウト可」などのルールは本書17章。ここではデータの形だけを扱う
- Solid Queue が自分用のテーブルを自動で作る（中身は設計しない。下の45テーブルには数えない）

### 8-2. 表記の読み方

| 表記 | 読み | 意味 |
| --- | --- | --- |
| bigint | ビッグイント | 大きい整数（ID など） |
| integer | インテジャー | 整数 |
| smallint | スモールイント | 小さい整数（選択肢の値など） |
| decimal | デシマル | 小数 |
| double precision | ダブルプレシジョン | 小数（計算結果の点数などに使う、倍精度の浮動小数点数） |
| string | ストリング | 短い文字列 |
| text | テキスト | 長い文章 |
| boolean | ブーリアン | はい／いいえ |
| date／datetime | デイト／デイトタイム | 日付／日時 |
| enum | イーナム | Rails の機能。DB（ディービー）には整数で保存し、コード上は名前で扱う選択肢 |
| NULL | ヌル | 空欄。「NULL 不可」は空欄禁止 |
| UNIQUE | ユニーク | 重複禁止。UNIQUE(a, b) は「aとbの組み合わせで重複禁止」 |
| CHECK | チェック | 値の範囲などを DB で制限する制約 |

### 8-7. 保存せず計算で出すもの

- 学生側の状態（応募済み／スカウトあり／マッチ済み）：やりとりの発生元と状態から導く
  - 応募済み：発生元が応募で、状態が未マッチ・見送り
  - スカウトあり：発生元がスカウトで、状態が未マッチ・見送り
  - マッチ済み：状態がマッチ・合格・不合格（発生元は問わない）
  - S3（募集管理）に出るもの：発生元が応募のもの（状態は問わない）と、発生元がスカウトで状態がマッチ・合格・不合格のもの
  - S4（スカウト管理）に出るもの：発生元がスカウトで、状態が未マッチ・見送りのもの（見送りは学生に見せないため）
- 企業側の「未対応応募」「スカウト済み」のタグ：状態が未マッチのやりとりの発生元から導く
- 「未返信」タグ：スレッドの最後の送信者から導く
- 稼働条件・性格の一致・ずれ：表示のたびに比較する
- おすすめ度 f(P, S)、Content、募集どうし・学生どうしの共起の値：必要なときに計算する（本書7-5）
