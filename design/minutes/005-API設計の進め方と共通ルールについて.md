### 2-2. 4-0 共通ルール（本書16-1）

| 番号 | 結果 | 内容 |
| --- | --- | --- |
| S103 | 承認 | ログイン後の画面では、データの取得・送信をすべてブラウザ側で行う（開発者の質問「一般的か」には、API サーバーを別に持つ構成では一般的な形（SPA）と回答） |
| PR2 | 承認 | REST＋JSON で作る。URL の先頭は /api/ で、バージョンは付けない |
| PR3 | 承認 | API の入口を、共通・企業用（/api/company/）・学生用（/api/student/）の3つに分ける |
| PR4 | 承認 | URL は名詞の複数形・snake_case。状態を変える操作は操作ごとに専用の URL にする。GET は読むだけに使う |
| PR5 | 承認 | POST・DELETE /api/session と GET /api/me。ログインはログアウトするまで続く |
| PR6 | 承認 | 守りは Rails に置き、画面側は見た目の振り分けだけにする |
| PR7 | 承認 | CSRF の合言葉は、Cookie で受け取ってヘッダーで送り返す（Django と同じ形） |
| PR8 | 承認 | JSON は、キー名が snake_case、日時が時差付きの ISO 8601、空欄が null、選択肢が英語の名前 |
| PR9 | 承認 | 選択肢と表示名は Rails の1か所で持ち、フォーム用に API で返す |
| PR10 | 承認 | HTTP ステータスの使い分けと、エラーの形（message＋errors） |
| PR11 | 承認 | ページ分けはページ番号方式で、1ページ20件 |
| PR12 | 承認 | 日本時間で数える。「ログイン中の操作」は、ログインした状態での API の呼び出しすべて |
| PR13 | 承認 | 画面の URL は /company/…・/student/… で始める。19画面の URL と、通知の移動先の形 |
| PR14 | 承認 | Route Groups で画面のフォルダをログイン前（auth）・ログイン後（main）に分ける。/api/me はどちらでも呼び、401 でログイン画面へ移すのは main 側だけ |
