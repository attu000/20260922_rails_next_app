# 議事録006：API のエンドポイント（Phase 4-1）について

- 日付：2026-09-22
- 参加：開発者、Claude（設計を支援する AI）
- 扱った範囲：Phase 4-1 エンドポイント一覧（6つのまとまり、全44本）

## 1. 話し合ったこと

- 4-1 を6つのまとまりに分け、課題の流れ（登録 → 募集 → スカウト・応募 → マッチ → メッセージ）の順に1つずつ決めた
- 他の AI から2件の指摘を受け、共通ルールに書き足した
  - PR24：ログイン画面で呼ぶ /api/me の 401 の返事に、合言葉（CSRF）の Cookie が付かず、誰もログインできなくなる恐れ
  - PR45：読むだけの窓口に他社の募集の番号が通ると、他社でのやりとりが見えてしまう恐れ
- 画面S2 の稼働条件の絞り込みを、開発者の意向で「自分の稼働条件で絞る」の切り替えから、「選択ボタン＋おすすめ順のときの自動選択」に変えた（PR34・PR37）
- 「募集新規作成ボタンを押したときの API はないのか」という質問に、「画面の移動だけで API は呼ばない。保存のときに作る」と回答した
- PR30（画面ごとの呼び出し表を各まとまりに付ける）は取り下げ、代わりに、4-1 をまとめて反映するときに「画面ごとの URL 一覧」（画面の URL と API の URL の両方）を作ることにした
