## 5. 途中でわかったこと

| わかったこと | 対処 |
| --- | --- |
| Gemfile に部品を足したあと、`docker compose exec backend bundle install` が「service is not running」になった。Rails のコンテナが止まっていたうえ、部品が入っていない状態では Rails が起動できない | 使い捨てのコンテナで実行する `docker compose run --rm backend bundle install` を使った（開発環境.md の 18-3） |
| Pagy のソースを読むと、数でないページ番号は1ページ目、範囲外のページは空の一覧になる | テストで確かめ、画面は範囲外のとき「このページに募集はありません」と出す |
| `useSearchParams`（URL の `?` の後ろを読む仕組み）を使う部品は、`<Suspense>` で包まないと本番の組み立て（`next build`）が失敗する（手元の Next.js の説明書） | 募集一覧の入れ物で包んだ |
| 条件欄の薄い例文を「例：Ruby、バックエンド、会社名」にしたが、当時の対象では「バックエンド」は合わなかった（AI の書き間違い） | PR198 で職種の名前が対象になったので、このままで正しくなった |
| 受け取る値の一覧（strong parameters）で、名前付きの値のあとにふつうの値を書くと Ruby の文法の誤りになる | テストの前に気づいて並べ替えた |
| 継続期間の選択肢（1／3／6／9／12）に2がなく、テストの募集が保存できない値になっていた | テストの値を条件ごとに分けた |
| 字下げを直すために PowerShell でファイルを書き直したら、改行が CRLF になった | `.gitattributes` の決まり（LF）に戻した |
| 職種の入力欄は大分類のチェックを中で覚えているので、ポップアップを閉じると消え、「この条件をクリア」でも残って見えた | 検索の条件欄が大分類のチェックを覚えて、開き直すときに渡す。クリアのときは部品を作り直す |
