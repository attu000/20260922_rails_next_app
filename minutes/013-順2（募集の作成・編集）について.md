### 3-6. 決めた細部

- 募集のテーブルは、順2 で使う【コア】の列だけを作った。カルチャーの5列は順9（【強み】）、目的・採用につながる可能性・求める人材の列は【仕上げ】で足す
- 募集の保存は、モデルの `save_posting` 1か所にまとめる（技術構成.md の 9-1-1 の4）。企業プロフィールと同じく「先に全部確かめてから、トランザクションの中で書き込む」順。職種は、同じ中分類が主から関連に移ることがあるので、まとめて消してから作り直す。主と関連の片方だけが送られてきたら、送られなかった側は今の内容のままにする
- 新規作成では「終了」を選べない（Rails は 422、画面は選択肢から外す）。勤務地の番号が都道府県にないときは「勤務地は一覧にありません」
- 任意の文章が空白だけなら、空欄（null）にそろえて保存する。インターンですることも対象（空白だけで掲載中にされるのを防ぐため）
- 初期データでは、設計書の表にある読み仮名（「DX（ディーエックス）」など）を入れない
- マイグレーションでは、目印（インデックス）と CHECK を `create_table` の中に書く。取り消しのときにテーブルと一緒に消え、失敗しないようにするため
- SWR の使い方
  - 失敗しても自動でやり直さない（401・403・404 はやり直しても同じため）
  - 選択肢は、ページを読み込み直すまで1回だけ取る（今までの手作りと同じ動き）
  - フォームは、最新を取り終えてから最初の値を入れる。保存に成功したら、SWR が覚えている中身も保存後の内容に差し替える
  - ログイン後の画面で SWR の取得が 401 になったら、共通の枠がまとめてログイン画面へ移す
- 募集一覧の画面の移動だけのボタンは、ボタンの見た目をしたリンクにする（新しいタブでも開ける）。0件のときは「まだ募集がありません」の一文だけ
- 編集画面の URL の番号は、符号化してから API の URL に入れる。番号が数字でない・他社の募集などは、そのまま Rails に聞き、404 の「見つかりません」を出す
