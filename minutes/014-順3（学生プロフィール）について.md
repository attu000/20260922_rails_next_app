## 3. 決めたこと

### 3-1. 範囲の決まり（開始時期・卒業年度）

| 番号 | 結果 | 内容 |
| --- | --- | --- |
| PR182 | 開発者の提案で変更して承認 | 提案は「開始時期（今月から12ヶ月先まで）と卒業年度（今年から10年後まで）の範囲は、値を変えたときだけ確かめる」。一度保存した値が、時間がたつと範囲の外になり、名前だけ直そうとしても保存できなくなるため。開発者から「開始時期は、募集の開始時期と同じく年と月を選べるようにして、制限をなくしてよい」「卒業年度は選択にした方がよい。選択肢に出る年が今年〜10年後なだけで、これも制限をなくしてよい」と提案があった。**開始時期・卒業年度とも、Rails 側の範囲の制限をなくす**。開始時期は年と月の2つの選択欄（年は募集と同じ1年前〜2年後）。卒業年度は選択欄（今年〜10年後）。どちらも、保存済みの年が範囲の外ならその年も選択肢に出す |

### 3-2. 大学

| PR183 | 承認 | 大学マスタに、デモ用に代表的な大学を20校入れる。学校コードは、文部科学省の学校コード一覧（令和8年5月1日時点。CSV を直接読んだ）の実際の値。国立11校、公立2校、私立7校 |

### 3-4. 決めた細部

- 順3 では、段階タグの【コア】の分だけを作った
  - 付属テーブルは3つ（プログラミング歴、興味のある職種、出社できる都道府県）
  - 性格5軸の列は順9（【強み】）で足す
  - 外部リンク・資格・興味のある業界・就活希望エリアは【仕上げ】で足す
  - 最初の説明では「付属テーブル7つを保存する」としていたが、ページ設計のマイページの段階タグを読み直して訂正した
- 大学マスタは表示順の列を持たないので、学校コードの順に並べる。コードの形から、北から南へ、同じ都道府県の中では国立 → 公立 → 私立の順になる
- 学部・学科は仮データ
  - 学部は6つ（工学部、理学部、情報学部、文学部、経済学部、その他）
  - 学科は各学部に数個ずつ入れ、どの学部も最後に「その他」を持つ
  - 学科は「学部と名前の組」で重複不可（「その他」が学部ごとにあるため）
- 学科が選んだ学部のものでなければ「学科は、選んだ学部の中から選んでください」。画面では、学部を変えると学科を空に戻す
- プログラミング歴
  - レベルは必須、年数は任意（0〜50 の 0.5刻み）
  - 0.5刻みかどうかは、データベースに入れる前の、送られたままの値で確かめる（小数点以下1桁の列に入れると、1.04 が 1.0 に丸められて気づけないため）
  - 保存のたびに「消して作り直す」
  - 窓口で返すとき、年数は数値に直す（そのままだと "1.5" と文字列になる）
  - 新しい行のレベルは空にし、本人に選んでもらう
- 活動状況は、モデルで必須にした。試しの学生（初期データ）とテスト用の学生にも入れた
- 画面の部品の共通化
  - 入力欄の部品・開閉するまとまり・年と月の選択欄・値の変換を、募集詳細編集から共通のファイルに移した
  - アイコン欄を、企業プロフィール編集から共通のファイルに移した
  - 2画面の見た目と動きは変えていない
- マイページの見た目：募集詳細編集と同じく、6つのまとまりを開閉する形（最初は「基本」だけ開く）
  - 稼働条件の文言は、学生は上限を入れるので「週◯日まで」「1日◯時間まで」「◯ヶ月以上続けられる」
  - 出社できる都道府県は47個あって長いので、開閉する行の中に入れ、「◯件選択中」を出す
  - 卒業年度は「2028年卒」の形
- プログラミング歴を変えたら、プログラミング歴のエラーを消す（エラーの名前に行の番号が入っているので、行を足したり消したりすると別の行の下に出てしまうため）
- 設計書の「名前」は、エラーの文では「氏名」とする（権限_バリデーションの必須の表と同じ）

## 5. 途中でわかったこと

| わかったこと | 対処 |
| --- | --- |
| 設計書の範囲の決まり（開始時期は今月から12ヶ月先、卒業年度は今年から10年後）のままだと、時間がたつと保存済みの値が範囲の外になり、ほかの項目も保存できなくなる | PR182 で範囲の制限をなくした |
| テストで、中身の入ったプログラミング歴の行がすべて「技術もレベルも空」として扱われた。Rails の `symbolize_keys` は外側の名前だけをシンボルにし、中の各行は「名前が文字列の普通の辞書」にしてしまうため、`row[:technology_id]` で取り出せなかった | 各行を、文字列でもシンボルでも取り出せる形（`with_indifferent_access`）に直してから使うようにした |
| 同じ技術が2行・51行のテストで、エラーの文を作るところで止まった（500）。Rails はエラーの文を作るとき、その項目の今の値を読みに行くが、学生プロフィールに `skills` という名前の項目がなかった | `skills` の名前でプログラミング歴を読めるようにした（外からは呼べないようにした。`alias_method` で作った別名には `private` の区切りが効かないので、個別に指定した） |
| `skills[0].years` という名前のままエラーの文を作ると、Rails が項目名を見つけられず「Skills[0] years は…」になる | 学生プロフィールに、「`skills[数字].〇〇` の項目名は、プログラミング歴の1行の項目名を使う」という引き方を足した |
| 「は入力しないでください」の文言が、日本語の言葉集（rails-i18n）にあるか手元で確かめられなかった | 自分で文言集（ja.yml）に書いた |
| 大学の学校コードは、文部科学省のページから CSV で取れた | 20校すべてを見つけ、廃止されていないことを確かめてから入れた |
