### 3-2. 画面の見た目

| 番号 | 結果 | 内容 |
| --- | --- | --- |
| PR141 | 変更して承認 | 当初の提案は「shadcn/ui を入れ、見た目の方針を3つ（部品集、色と余白の基準、画面の骨組み）に分けて決める」。開発者が「細かい見た目は後回しでよい。shadcn/ui の使い方を知りたい。複雑なら後回しでもよい」とし、解説のあと「shadcn/ui は今入れ、細かい見た目は決めずに最低限をそろえる」で承認。後から見た目を1か所で整えられるようにするには、画面が少ない今入れるのが最も安いため |
| PR146 | 承認 | shadcn/ui の部品の動きは Base UI にする。2026年7月から shadcn/ui の標準が Radix UI から Base UI に変わっていた（調べて分かった）。公式の説明と手元のコードの形をそろえるため |
| PR147 | 承認 | 色や形は標準のプリセット（`base-nova`）のまま導入する。色の系統（`neutral`）と色の変数での管理（`true`）は、導入した後から変えられない |
| PR149 | 承認 | 「読み込み中…」「エラーが起きました」などの文字の色も、色の名前ではなく shadcn/ui の変数（`text-muted-foreground`、`text-destructive`）で書く。後で色を整えるときに `globals.css` を直すだけで全体に効かせるため |

## 4. 途中でわかったこと

| わかったこと | 対処 |
| --- | --- |
| shadcn/ui の標準が、2026年7月から Radix UI ではなく Base UI になっていた | PR146 で Base UI にした |
| `init` を実行すると、`cn` という部品が入り、`lib/utils.ts` が1行になった | 2026年9月に shadcn/ui が公開した公式の部品。npm の記録で、管理者が shadcn 本人、ソースが `github.com/shadcn-ui/cn`、出どころの証明（provenance）付きであることを確かめた |
| `package-lock.json` が約3,300行増えた | `globals.css` が `shadcn` の部品の中の CSS を読み込むので、`shadcn` そのものが部品に入ったため。ブラウザに届くのは CSS だけ |
| `init` が「書体の更新」と表示したのに `app/layout.tsx` を書き換えず、`globals.css` の `--font-sans` が自分自身を指していた | `app/layout.tsx` の Geist の `variable` を `--font-sans` にして直した（開発環境.md の 18-4） |
| 画面が OS のダークモードで自動的に黒くならなくなった | `dark` の印を付けたときだけ黒くなる形になったため。当面は常に白い画面でよい |
| `docker compose exec` は、コンテナが起動していないと「service is not running」になる | 先に `bash dev.sh start` で起動する。`npx` は、初回に shadcn のコマンドをダウンロードしてよいかを聞く |
