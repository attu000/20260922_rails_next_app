### 3-5. 決めた細部

- 企業の窓口は `Api::Company::BaseController` を親にし、種別の確認（学生なら 403）をここ1か所に書く。前処理の順は「CSRF の Cookie → 合言葉の確認 → ログインの確認（401）→ 種別の確認（403）」なので、未ログインには 401 が返る
- アイコンの URL は、jbuilder の部品（`api/shared/_icon_url`）1つで作り、⑧⑨⑩ と形A で使い回す。学生のプロフィールにアイコンを足せば（順3）、そのまま学生の URL も出る
- ⑩ は、送られたものがファイルでなければ先に 422 で弾く（Active Storage は文字列を「保存済みのファイルの番号」と解釈するため）
- 新しいエラー文言：「◯◯に選べない値が含まれています」「◯◯に同じ値が重複しています」「アイコンはPNG・JPEG・WebPのいずれかにしてください」「アイコンは2MB以下にしてください」
- 画面側の人数の選択欄は、shadcn/ui の `Select` ではなく `Native Select`（ブラウザ標準の `<select>` に見た目を付けたもの）
- ⑦ は、ページを読み込み直すまで画面側で取っておき、使い回す。失敗は取っておかない
- 企業プロフィール編集で保存したら、ヘッダーの会社名・アイコンを取り直す（`useRefreshMe`）。ログイン後の画面では、どの API の 401 でもログイン画面へ移す（`useRedirectIfUnauthorized`）
- アイコンは保存を押すまで送らず、ブラウザの中だけでプレビューを出す。本体の保存に成功してアイコンだけ失敗したときは、本体の保存を取り消さず「会社情報は保存しましたが、アイコンは保存できませんでした」と出す
- 保存した後は、企業プロフィール編集の画面に留まる
